# MPPI Examples

These examples plan the motion of a point mass and a unicycle using model
predictive path integral control (MPPI). `SamplingPlanner`, `GaussianProposal`,
and `MPPI` live in `gtsam/planning`. The robot models live in
`gtsam_unstable/planning`. Building the examples requires `GTSAM_BUILD_UNSTABLE`.

A Gaussian proposal draws control sequences around the current plan. The
planner rolls each sequence forward with the supplied dynamics, then scores
the resulting states and controls with a factor graph. MPPI weights the
samples by their scores, giving cheaper trajectories more influence on the
next mean control sequence.

## Examples

| Example | Robot | What it shows |
|---|---|---|
| [PointMassMPPITrajectoryOptimizationExample](https://github.com/borglab/gtsam/blob/develop/gtsam_unstable/examples/mppi/PointMassMPPITrajectoryOptimizationExample.cpp) | A point mass in the plane: state [px, py, vx, vy], control the acceleration [ax, ay] | Trajectory optimization from rest at the origin to rest at (3, 2) in 3 s. |
| [UnicycleMPPITrajectoryOptimizationExample](https://github.com/borglab/gtsam/blob/develop/gtsam_unstable/examples/mppi/UnicycleMPPITrajectoryOptimizationExample.cpp) | A unicycle: state a `Pose2`, control [v, omega], the forward speed and the yaw rate | Trajectory optimization for a robot that cannot move sideways, from the origin facing along x to (3, 2) facing along y in 3 s. |
| [UnicycleMPPIMPCExample](https://github.com/borglab/gtsam/blob/develop/gtsam_unstable/examples/mppi/UnicycleMPPIMPCExample.cpp) | The same unicycle, simulated with process noise | Model predictive control toward the same goal, until the unicycle is within 0.05 m and 0.1 rad of it. |

The point-mass example supplies a vector field returning velocity and
acceleration. The two unicycle examples supply a discrete transition returning
the next pose. All three score state and control priors. The open-loop unicycle
also includes its hard dynamics factors in the graph. Their errors vanish on
trajectories generated by that same transition.

## Trajectory Optimization and MPC

The two trajectory optimization examples call `optimize()` once. MPPI runs 30
iterations on one problem and returns an open-loop plan of the controls and
the states over the whole horizon. Both plans end within 3 cm of the goal.

The MPC example runs the same optimization in a receding-horizon loop. At
every control step, x_0 is set to the current pose, the controls are
warm-started with the previous plan shifted by one step, MPPI runs one
iteration, and only the first control is applied. The simulated unicycle
drifts from the plan because of its process noise, and each new plan starts
from the pose it reached. It reaches the goal tolerance in under 5 s of
simulated time.

## Building and Running

From a GTSAM build folder, build and run an example with its `.run` target:

```
make PointMassMPPITrajectoryOptimizationExample.run
make UnicycleMPPITrajectoryOptimizationExample.run
make UnicycleMPPIMPCExample.run
```

The trajectory optimization examples print the cost of the initial and of the
optimized plan, the plan every 0.5 s, and the final distance to the goal. The
MPC example prints the pose and the applied control every 0.5 s, and the time
at which it reached the goal.
