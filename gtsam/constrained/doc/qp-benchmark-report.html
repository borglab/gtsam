QP solver benchmarks

This report compares seven solvers on fixed quadratic programs from robotic control and humanoid trajectory optimization. It measures complete solver calls and independently checks returned solutions against the original problem. The GTSAM entries are Dense Dual, Sparse Dual, and the direct Gaussian augmented Lagrangian solver with QR disabled.

Dense Dual and Sparse Dual certify all 256 MPC combinations. DAQP is fastest on the small MPC families; Dense Dual is the strongest GTSAM option there. Larger G1 problems favor different sparse methods. The plots count failures instead of rewarding fast unsuccessful returns. Interactive charts require an internet connection to load Plotly 3.1.0.

Measurement and accuracy

The 64 public MPC problems run at four settings, producing 256 combinations per solver. Default uses each solver’s native tolerances and an external acceptance threshold of 1.0; it is not an equal-accuracy comparison. The other settings request absolute tolerances of 1e-3, 1e-6, or 1e-9, and use that threshold for the external certificate. A certificate requires native success, finite original-QP primal and stationarity residuals, absolute duality gap, and correctly signed inequality multipliers.

Each MPC combination receives an initial call and five fresh repetitions. Timings are medians of those five repetitions. Profiles use a case only if all six calls certify; all 64 cases remain in each denominator (four in QUAD-only profiles). The horizontal axis is time divided by the fastest certified solver for that case. A curve reaching farther left is faster; a curve ending lower has more failures.

GTSAM timing starts with assembled native factors, before solver construction, and includes setup, ordering, equality handling, initialization, optimization, multiplier recovery and output conversion. Input matrix-to-factor translation and independent scoring are excluded. External solvers retain their upstream matrix-input setup and solve boundaries. Cold starts and fresh solver caches are used throughout. MPC calls run serially on CPU 0, with one TBB/numerical thread and a 10-second native watchdog; profiling is disabled.

ALM uses the direct Gaussian solver with params.lmParams.multifrontalParams.qrMode = QRMode::Off, BCL defaults, 20 outer and 100 inner iterations, and no added objective regularization. Explicit MPC accuracies change its absolute violation and stationarity tolerances. Both dual GTSAM solvers use requested proximal weight 1e-9 on MPC and zero additional regularization on G1. DAQP keeps its native selective proximal treatment of weak curvature. WALK/BAL use vector blocks; QUAD retains state/contact blocks.

QR-off ALM was measured on November 8 with 1,536 MPC calls. Dense Dual, Sparse Dual and DAQP use the corresponding November 8 campaign; ProxQP, Clarabel and OSQP retain November 7 measurements on the same inputs and hardware. The source campaigns and fingerprints are recorded below; this report edit does not claim that every solver was rerun together.

G1 humanoid QPs

These are three fixed application QPs, with 18,549 to 193,566 variables. G1 calls use up to eight TBB/solver threads on CPUs 0–7, one numerical-library thread, a 300-second watchdog and a 16 GiB memory cap. External solvers retain their recorded supported thread settings; OSQP uses its serial sparse backend. Objective factors, original inverse sigmas and application damping are preserved. No additional objective regularization is added. All original feasibility, stationarity, sign and absolute-gap thresholds are 1e-7; complementarity is recorded separately.

The table uses primary complete-call times, not medians. GTSAM times exclude native factor reconstruction; external setup/solve times exclude separately recorded Hessian conversion. Five additional G1SP20 observations are available in the JSON for the retained successful external and Sparse Dual calls; other G1 results are single observations.
