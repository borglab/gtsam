# ComponentWise vs. Logmap IMU Factor Errors

This report compares the `ComponentWise` and `Logmap` IMU factor-error charts
for all four GTSAM preintegration backends. It supports making the
$SE_2(3)$ Logmap the default for newly constructed `PreintegrationParams` and
`PreintegrationCombinedParams` objects.

The values below are generated by the executed
[Galilean IMU factor NEES notebook](./GalileanImuFactorNEES.ipynb). The
notebook is the executable source of truth and includes the Monte Carlo code,
assertions, confidence intervals, and plots. This Markdown file is a compact,
downloadable comparison for design review.

## How to read the tables

Normalized Estimation Error Squared (NEES) tests whether the residual and its
predicted covariance agree. The theoretical mean is the residual dimension:
9 for the standard IMU factor and 15 for the Combined IMU factor. A value
closest to that mean is best; a numerically smaller NEES is not automatically
better. Bold NEES values are closest to the theoretical mean within each
experiment. Bold physical errors and mean residual norms are the minima, with
ties retained.

The error chart and preintegration backend answer different questions:

- `Logmap` versus `ComponentWise` selects how a factor expresses navigation
  error.
- Manifold, Tangent, Lie-group, and Galilean select how IMU measurements and
  covariance are preintegrated.

## Experiment 1: one-second inertial stress test

This experiment integrates simultaneous high rotation and acceleration at
20 Hz. Its expected mean 9D NEES is 9, with a 95% interval of approximately
[8.849, 9.152].

### Physical endpoint error

| Backend | Position RMS (m) | Velocity RMS (m/s) |
|---|---:|---:|
| Manifold | 0.0578 | 0.1049 |
| Tangent | 0.0578 | 0.1049 |
| Lie group | 0.0578 | 0.1049 |
| Galilean | **0.0427** | **0.0767** |

### Factor error and NEES

| Error mode | Backend | Mean NEES | Mean residual norm |
|---|---|---:|---:|
| ComponentWise | Manifold | 14.506 | 0.0818 |
| ComponentWise | Tangent | 14.511 | 0.0818 |
| ComponentWise | Lie group | 14.506 | 0.0818 |
| ComponentWise | Galilean | 8.958 | **0.0011** |
| Logmap | Manifold | 14.502 | 0.0818 |
| Logmap | Tangent | 14.507 | 0.0818 |
| Logmap | Lie group | 14.502 | 0.0818 |
| Logmap | Galilean | **8.959** | **0.0011** |

The two factor charts cannot correct finite-rate preintegration error: the
three established backends are overconfident in this deliberately stressful
20 Hz case under either chart. Galilean has both the lowest physical endpoint
error and statistically consistent NEES.

This Monte Carlo experiment isolates accumulated IMU uncertainty. The expected

## Why Logmap should be the fresh-object default

The long-horizon experiments expose a systematic chart effect that the short
experiments do not: ComponentWise residuals are biased relative to the
preintegrated covariance, while Logmap residuals remain consistent for every
backend and for both 9D and 15D factors. Logmap also expresses rotation,
position, and velocity error as one coupled $SE_2(3)$ tangent vector instead of
mixing separately defined component errors.

Therefore:

1. Fresh standard and Combined parameters should select `Logmap`.
2. `Legacy` should remain an explicit opt-in for historical backend-dependent
   behavior.
3. `ComponentWise` should remain available for applications that explicitly
   require a uniform component-wise chart.
4. Version-0 archives should continue loading as `Legacy`, while version-1
   archives restore their stored mode.

This changes only the factor residual default. It does not change the NavState
optimization chart or any preintegration-backend CMake default.

## Which preintegration backend to use

| Backend | Recommended use | Evidence and caution |
|---|---|---|
| **Galilean** | High dynamics, simultaneous rotation and acceleration, lower IMU rates, longer preintegration intervals, or rotating-Earth navigation with `omegaCoriolis` configured. | It has the lowest physical errors and consistent Logmap NEES in every correctly modeled experiment here. It is newer, so confirm required wrapper, serialization, and downstream feature coverage. |
| **Tangent** | General-purpose production use, existing Tangent-based systems, or workflows requiring PIM `mergeWith`. | Its long-horizon Logmap NEES is consistent, but it retains the finite-rate coupled-motion error visible at 20 Hz. |
| **Manifold** | Reproducing the original on-manifold formulation or maintaining historically validated results. | Its Logmap NEES is consistent, but this benchmark shows no accuracy advantage over Tangent or Lie-group preintegration. |
| **Lie group** | Work that specifically requires applying each increment with the $SE_2(3)$ group exponential or aligning with a Lie-group derivation. | Its results match Manifold in these experiments; select it for formulation semantics rather than an assumed NEES advantage. |

Factor topology is a separate decision. Use `CombinedImuFactor` when bias
random walk and state-bias cross-covariances belong in one 15D factor. Use
`ImuFactor` or `ImuFactor2` when bias evolution is modeled separately.

## Compatibility opt-outs

To restore historical backend-dependent behavior:

```cpp
params->setImuFactorErrorMode(ImuFactorErrorMode::Legacy);
```

To force uniform ComponentWise behavior:

```cpp
params->setImuFactorErrorMode(ImuFactorErrorMode::ComponentWise);
```

In Python, use the corresponding `gtsam.ImuFactorErrorMode` enum values.
